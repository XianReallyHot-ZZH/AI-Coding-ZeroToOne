## 1. 产品概述

### 1.1 产品背景

随着 AI 图像生成技术的快速发展，越来越多的工具开始探索"文本到幻灯片"的自动化流程。Manus 和 NotebookLM 等产品已经展示了 AI 生成 Slides 的可行性——其核心思路是：将文本内容拆分为多页，逐页生成视觉一致的图片，再以幻灯片形式串联播放。

Google 最新推出的 Nano Banana Pro（即 Gemini 3 Pro Image，模型名 `gemini-3-pro-image-preview`）具备原生图文混合生成能力，支持 16:9 宽高比和多种分辨率输出，并可通过风格参考图片实现视觉一致性，非常适合用于此类场景。

### 1.2 产品定位

GenSlides 是一个本地运行的单页应用（SPA），它：
- 接收用户输入的文本内容（主题或大纲），自动拆分为多页 Slide
- 调用 Nano Banana Pro 为每页生成视觉风格统一的图片
- 提供走马灯（Carousel）全屏播放体验
- 后端 Python，前端 TypeScript，纯本地部署，无需云服务

### 1.3 目标用户

- 需要快速制作演示文稿的个人开发者、创业者
- 希望用 AI 辅助生成视觉内容的内容创作者
- 对传统 PPT 工具感到繁琐、希望"一键生成"的效率用户

## 2. 核心功能需求

### 2.1 内容输入与 Slide 拆分

#### 2.1.1 功能描述

用户在左侧面板输入主题或大纲文本，系统调用 LLM 将内容拆分为多页 Slide，每页包含标题和要点。

#### 2.1.2 详细需求

| 需求ID | 需求描述 | 优先级 |
|--------|----------|--------|
| FR-001 | 提供文本输入区域，支持输入主题描述或结构化大纲 | P0 |
| FR-002 | 支持设置 Slide 总页数（默认 5~10 页） | P0 |
| FR-003 | 调用 LLM 将输入内容拆分为多页 Slide 结构（标题 + 要点） | P0 |
| FR-004 | 拆分结果可在前端预览和手动编辑 | P1 |
| FR-005 | 支持重新生成拆分结果 | P1 |

用户可通过上传参考图片或输入文字描述来定义 Slides 的视觉风格，确保所有页面风格统一。

#### 2.2.2 详细需求

| 需求ID | 需求描述 | 优先级 |

### 2.3 图片生成

#### 2.3.1 功能描述

系统调用 Nano Banana Pro（`gemini-3-pro-image-preview`）为每页 Slide 生成图片，确保视觉风格一致。

#### 2.3.2 详细需求

| 需求ID | 需求描述 | 优先级 |
|--------|----------|--------|
| FR-020 | 调用 Nano Banana Pro API 逐页生成 Slide 图片 | P0 |
| FR-021 | 每次生成请求携带风格参考图片（如有）以保持视觉一致性 | P0 |
| FR-022 | 默认输出 16:9 宽高比，分辨率 1920×1080（1080p） | P0 |
| FR-023 | 支持用户选择分辨率：1K（1024×576）、2K（1920×1080）、4K（3840×2160） | P1 |
| FR-024 | 生成过程中显示进度条，标注当前正在生成第几页 | P0 |
| FR-025 | 单页生成失败时支持重试，不影响其他页面 | P0 |
| FR-026 | 生成的图片缓存到本地磁盘，避免重复调用 API | P1 |

#### 2.3.3 API 调用示例

```python
from google import genai
from google.genai import types
from PIL import Image
import io, base64

client = genai.Client()

# 加载风格参考图片（可选）
style_ref = Image.open("style_reference.png")

response = client.models.generate_content(
    model="gemini-3-pro-image-preview",
    contents=[
        types.Part.from_image(style_ref),  # 风格参考
        types.Part.from_text(
            "Generate a presentation slide image in 16:9 aspect ratio. "
            "Title: 'AI 时代的内容创作'. "
            "Key points: 1) 自动化生成 2) 风格一致性 3) 效率提升. "
            "Visual style: match the reference image style exactly."
        ),
    ],
    config=types.GenerateContentConfig(
        response_modalities=["TEXT", "IMAGE"],
    ),
)

# 提取生成的图片
for part in response.candidates[0].content.parts:
    if part.inline_data and part.inline_data.mime_type.startswith("image/"):
        image_bytes = part.inline_data.data
        image = Image.open(io.BytesIO(image_bytes))
        image.save("slide_01.png")
```

## 4. 用户场景

### 4.1 场景 1：快速生成产品演示

**用户**：创业者小陈

**背景**：小陈需要在明天的路演中展示产品概念，但没有设计师资源。

**操作流程**：
1. 小陈打开 GenSlides，在左侧输入框粘贴产品介绍文案
2. 设置页数为 8 页，上传公司品牌色调的参考图片
3. 点击"生成"，等待约 2 分钟
4. 在右侧预览区查看生成结果，微调第 3 页的顺序
5. 点击"全屏播放"，以走马灯形式预览完整效果
6. 满意后直接用于路演展示

**期望结果**：小陈在 5 分钟内获得了风格统一的演示幻灯片

## 5. 边界情况与错误处理

| 场景 | 处理方式 |
|------|----------|
| 用户输入内容过短（< 10 字） | 提示用户补充更多内容描述 |
| 用户输入内容过长（> 5000 字） | 截断并提示，或建议拆分为多次生成 |
| 风格参考图片格式不支持 | 仅接受 PNG/JPG/WEBP，其他格式提示错误 |
| 风格参考图片尺寸过大（> 10MB） | 后端自动压缩至合理尺寸后使用 |
| Nano Banana Pro API 返回错误 | 显示错误详情，提供重试按钮 |
| API 调用超时（> 60 秒） | 中断当前请求，提示用户重试 |
| API 配额耗尽 | 显示明确提示，建议用户检查 API 配额 |
| 生成的图片内容不符合预期 | 支持单页重新生成，可修改该页的 Prompt 后重试 |

### 6.3 API 设计

| 方法 | 路径 | 描述 |
|------|------|------|
| POST | `/api/slides/split` | 将输入文本拆分为 Slide 结构 |
| POST | `/api/slides/generate` | 为所有 Slide 生成图片 |
| POST | `/api/slides/{id}/regenerate` | 重新生成单页 Slide 图片 |
| GET  | `/api/slides` | 获取当前所有 Slides 数据 |
| PUT  | `/api/slides/reorder` | 调整 Slide 顺序 |
| POST | `/api/style/upload` | 上传风格参考图片 |

#### 关键接口示例

**POST `/api/slides/split`**

请求体：
```json
{
  "content": "AI 时代的内容创作：从文本到视觉的自动化革命",
  "slide_count": 8,
  "style_description": "科技感，深色背景，霓虹色调"
}
```

响应体：
```json
{
  "slides": [
    {
      "id": 1,
      "title": "AI 时代的内容创作",
      "points": ["文本到视觉的自动化", "创作效率的质变"],
      "prompt_hint": "封面页，大标题居中"
    },
    {
      "id": 2,
      "title": "传统内容创作的痛点",
      "points": ["设计门槛高", "耗时耗力", "风格难统一"],
      "prompt_hint": "列表页，三个要点配图标"
    }
  ]
}
```

### 6.4 部署方式

- 纯本地运行，无需云服务器
- 后端：`uvicorn main:app --reload`（开发模式）
- 前端：`npm run dev`（Vite 开发服务器），生产环境构建后由 FastAPI 静态文件服务托管
- 环境变量：通过 `.env` 文件配置 `GOOGLE_API_KEY`

## 8. 待确认事项

以下事项需要在设计阶段进一步确认：

1. **并发生成策略**：多页 Slide 是否并发调用 API 生成？并发数上限是多少？需根据 API 速率限制确定。
2. **图片导出格式**：除 PNG 外是否需要支持 PDF 导出（将所有 Slides 合并为一个 PDF 文件）？
3. **LLM 选择**：内容拆分环节使用哪个 LLM？是复用 Gemini 还是使用其他模型（如 DeepSeek）？
4. **离线模式**：是否需要支持已生成图片的离线浏览（无需 API 连接）？
5. **多语言支持**：Slide 内容是否需要支持英文等其他语言的生成？
